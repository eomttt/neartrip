# 가까이 · neartrip

여행 중 숙소에서 “오늘 어디 가지?”를 정하는 서비스입니다. 묵는 곳 근처의 맛집·카페·가볼 만한 곳을 골라 하루 동선을 만듭니다. 숙소로 돌아오는 동선이 기본이며 마지막 도착점은 따로 정할 수 있습니다.

## 실행

Node.js 22.12 이상이 필요합니다.

```sh
npm ci
npm run dev
```

화면은 http://127.0.0.1:5173, API 서버는 http://127.0.0.1:3001에서 실행됩니다. Vite가 `/api` 요청을 서버로 전달합니다. 기본 포트가 사용 중이면 기존 프로세스를 확인한 뒤 포트를 조정하세요.

## 두 가지 실행 모드

**예시 모드**: 카카오 키가 둘 다 없거나 `DEMO_MODE=true`이면 사용합니다. 가상 장소 8곳으로 검색·필터·선택·순서 변경·왕복 동선을 체험할 수 있습니다. 개략도는 실제 지도가 아니며, 선은 방문 순서만 나타냅니다. 예시 거리와 시간은 직선거리에 계수를 적용한 추정치입니다. 실제 여행 안내에 사용하지 않습니다.

**카카오 연동 모드**: `.env.example`을 참고해 루트에 `.env.local`을 만들고 아래 값을 설정합니다. 키가 한 개만 있으면 예시 모드로 조용히 전환하지 않고 설정 누락을 표시합니다.

```dotenv
KAKAO_REST_API_KEY=카카오_REST_API_키
VITE_KAKAO_JAVASCRIPT_KEY=카카오_JavaScript_키
DEMO_MODE=false
```

카카오디벨로퍼스에서 앱을 만들고 카카오맵을 활성화합니다. JavaScript 키의 허용 도메인에 `http://127.0.0.1:5173`과 `http://localhost:5173`을 등록합니다. 변경 후 개발 서버를 다시 실행합니다.

REST 키는 서버에서만 사용합니다. `VITE_` 접두사가 붙은 값은 브라우저 번들에 들어가므로 REST 키에는 붙이지 않습니다. `.env.local`은 Git에서 제외됩니다. 예시 모드는 외부 지도 API를 호출하지 않습니다.

## 1Password로 연결한 로컬 환경

이 Mac에서는 1Password Developer Environment `neartrip`을 프로젝트의 `.env.local`에 마운트했습니다. `KAKAO_REST_API_KEY`, `VITE_KAKAO_JAVASCRIPT_KEY`, `DEMO_MODE`를 보관하며 키 값은 저장소에 넣지 않습니다. 실행할 때 1Password가 잠겨 있으면 잠금을 해제하고 접근 요청을 승인하세요.

개발 서버는 환경변수를 한 번 읽은 뒤 API 서버와 Vite에 전달합니다. 1Password 마운트는 일반 파일과 달리 FIFO이므로 두 프로세스가 동시에 읽으면 한쪽에 빈 값이 들어갈 수 있습니다. 환경변수를 바꾼 뒤에는 `npm run dev`를 다시 실행하세요.

2026-09-10 실연동 검증에는 기존 `엄현태` 앱의 카카오맵 무료 쿼터를 사용했습니다. 새 `가까이 neartrip` 앱도 생성돼 있지만 유료 API 설정은 하지 않았습니다. 기존 앱의 도메인 6개를 유지하고 `http://127.0.0.1:5173`, `http://localhost:5173`을 추가했습니다. 다른 Mac에서는 별도로 키를 연결해야 합니다.

## 최소 기능

상단에 1. 출발·도착·주변 선택 → 2. 동선 보기 두 단계를 표시합니다. 첫 화면에서 출발점, 선택 도착점, 주변 방문지를 모두 고릅니다. 담은 장소의 순서 변경 창에서 방문 순서를 바꾸고 하단의 동선 생성 버튼을 누르면 바로 지도 화면으로 이동합니다. 장소·순서 수정은 첫 단계로 돌아가며 기존 선택을 유지합니다. 첫 화면에서는 주변 장소 목록만 스크롤합니다. 두 번째 단계에서 이동 안내를 누르면 지도 위로 바텀 시트가 올라옵니다. 닫기, 바깥 영역 클릭, Escape로 닫을 수 있습니다.

- 장소명·주소로 시작점 검색
- 시작점 반경 500m·1km·2km·3km의 맛집·카페·관광지 검색
- 목록 또는 지도에서 최대 5곳 선택·해제
- 담아둔 순서대로 동선 생성, 화살표로 방문 순서 변경
- 선택 도착점 검색·변경·삭제, 미지정 시 출발점으로 돌아오는 동선
- 방문지 없이 출발점에서 도착점으로 바로 가는 동선
- 구간별 이동 안내
- 구간 제목·세부 이동 안내를 누르면 지도 이동과 경로·도착 지점 강조
- 순서를 바꾸거나 장소를 제거하면 기존 경로를 즉시 비우고 다시 계산
- 빈 검색 결과, 호출 오류, 경로 없음, 키 누락 표시

장소 검색 결과 자체가 맛집 품질을 보증하지 않습니다. 첫 버전은 거리와 카테고리로 후보를 보여줍니다. 장소 카드에서 주소와 카카오맵 후기·상세 링크를 제공합니다. 공식 장소 검색 API는 평점·블로그 본문을 제공하지 않으므로 상세 페이지를 새 창으로 열어 확인합니다. 예시 장소처럼 상세 URL이 없으면 링크를 만들지 않습니다. 리뷰·평점·영업시간·사진을 임의로 생성하지 않습니다. [공식 응답 필드](https://developers.kakao.com/docs/ko/kakaomap/rest-api)에서 제공 범위를 확인할 수 있습니다. 날짜·체류시간·예약·로그인·저장은 이번 범위에서 제외했습니다.

## 방문 순서와 이동 조건

화면의 **순서대로 동선 짜기** 버튼은 담아둔 순서를 그대로 사용합니다. 화살표로 순서를 바꾼 뒤 같은 버튼을 누르면 변경한 순서대로 각 구간의 실제 경로를 조회합니다. 선택한 도착점이 있으면 그곳에서 끝내고, 없으면 출발점으로 돌아옵니다. 도착점은 방문지 5곳과 별도로 지정하며, 이미 담은 장소를 도착점으로 고르면 중간 방문지에서 옮깁니다. 도착점 변경·삭제 시 기존 경로를 비우고 다시 계산합니다. 구간 조회는 최대 세 개를 동시에 요청합니다. API는 기존 `nearby` 옵션도 지원하지만 화면에서는 `manual` 옵션만 사용합니다.

먼저 도보 경로를 조회합니다. 20분 이내라면 사용하고, 초과하거나 경로가 없으면 대중교통 후보를 조회합니다. 버스·지하철 5정거장 이내이고 연결 도보 합계가 20분 이내인 경로를 우선합니다. 출발·환승·도착 사이 빠진 도보를 별도 조회하며, 좌표 사이 10m 이하는 같은 지점으로 봅니다.

**20분·5정거장은 권장 기준입니다.** 기준에 맞는 경로가 없으면 완성된 후보 중 이동 시간이 짧은 경로를 선택하고, 초과 이유를 경고로 표시합니다. 경고가 있어도 조회된 선·구간 안내·시간·거리를 유지합니다. 연결 도보 일부를 찾지 못하면 조회된 구간만 표시하고 누락을 알립니다. 실제 경로가 전혀 없을 때만 선을 생략하며, 확인하지 못한 구간을 가짜 직선으로 연결하지 않습니다. 지도에서는 도보를 실선, 대중교통을 점선으로 표시합니다.

**정거장 수는 실응답으로 검증했습니다.** 2026-09-10 지하철과 버스 응답에서 `stops`에 승차·하차 지점이 모두 포함되는 것을 확인했습니다. 각 탑승 구간의 목록 길이에서 1을 빼고 환승 전후 값을 합산합니다. 성수→건대입구는 1정거장, 성수→잠실은 5정거장으로 권장 기준에 맞습니다. 성수→잠실새내는 6정거장으로 경고와 함께 표시합니다. 목록이 없거나 두 지점보다 적으면 정거장 수를 확인할 수 없다는 경고를 표시합니다.

API가 반환한 후보 안에서만 조건을 검사합니다. 다른 방문 순서를 재탐색해서 이동 제한을 충족하는 전체 코스를 찾아내는 기능은 아직 없습니다. 사용자가 순서를 바꾸고 다시 조회할 수 있습니다.

## 검증 상태

키 없이 실행하는 API 통합 테스트, 컴포넌트 테스트와 경로 응답 테스트 58개를 제공합니다. 2026-09-10에 테스트, TypeScript 검사, 빌드, 포맷 검사를 통과했습니다. 승차역 제외, 5정거장 경계, 환승 합산, 연결 도보 누락·시간 초과를 회귀 테스트로 검사합니다.

2026-09-09에는 실제 브라우저에서 예시 모드의 검색, 카페 필터, 500m 반경 필터, 목록·지도 선택, 최대 5곳 제한, 왕복 동선 생성, 순서 변경 후 재계산, 출발점 변경 시 일정 초기화를 확인했습니다. 390×844 모바일 화면에서도 가로 넘침 없이 검색·지도·일정이 표시됐고, 확인한 흐름에서 브라우저 콘솔 오류와 경고는 없었습니다.

2026-09-10에는 카카오 실호출로 성수역 검색, 주변 카페 조회, 도보 왕복 동선, 지하철 1·5정거장 우선 적용을 확인했습니다. 권장 기준으로 바꾼 뒤에는 성수↔잠실새내 6정거장 왕복 경로가 경고와 함께 각각 183개 좌표를 유지하는 것도 확인했습니다. 대림창고↔건국대학교 일감호에서는 지하철·버스 환승과 빠진 연결 도보를 포함한 왕복 경로도 확인했습니다.

실제 지도 화면에서 검색, 카페·500m 필터, 목록·지도에서 3곳 선택, 왕복 동선 생성, 방문 순서 변경과 수동 재계산을 확인했습니다. 390×844 모바일 화면에서도 실제 지도와 일정이 표시됐으며 가로 넘침과 브라우저 콘솔 오류·경고는 없었습니다.

```sh
npm run check
npm run format:check
```

예시 모드로 성수역 검색, 카페 필터, 장소 3곳 선택, 동선 생성, 순서 변경, 다시 조회, 출발점 변경 순으로 확인할 수 있습니다. 다른 지역이나 다른 앱 키로 연결할 때도 역 한 구간, 환승, 도보 전용, 경로 없음, 권한 오류를 확인하세요.

구간별 이동의 제목을 누르면 해당 구간 전체를, 세부 안내를 누르면 해당 경로만 지도에서 강조합니다. 선택한 경로 위로 주황색 표시점이 이동하며, 4초 동안 진행한 뒤 끝에서 1초 머물고 반복합니다. 다시 누르면 처음부터 재생합니다. 지도에 이동 미리보기라고 표시하며 실제 사용자 위치나 이동 속도를 나타내지 않습니다. 도보 실선·대중교통 점선 구분은 유지합니다. 구간 선택 시 바텀 시트를 닫고 지도에서 경로를 보여주며, 동작 줄이기 설정에서는 표시점을 움직이지 않고 강조합니다. 일정 변경 시 이전 강조를 제거합니다. 지도를 유지한 채 이동 안내를 바텀 시트로 표시합니다. 시트의 출발·도착 정보는 고정하고 구간별 이동 안내 안에서 스크롤합니다. 시트를 닫아도 지도 중심과 확대 수준은 유지합니다. 목록을 접고 펼쳐도 선택한 구간의 초점이 유지되며, 창 크기를 바꿀 때도 현재 중심과 확대 수준을 보존합니다.

2026-09-10 실제 지도에서 구간과 세부 안내를 선택하면 해당 경로를 강조하는 것을 확인했습니다. 390×844 화면에서 지도가 화면 안으로 이동하고 가로 넘침이 없었습니다. 테스트로 키보드 선택, 반복 재생, 일정 초기화, 경고·경로 없음 구간의 강조를 검사합니다.

## 디자인 시스템

[shadcn/ui](https://ui.shadcn.com/docs/installation/vite)의 Button, Input, NativeSelect, Dialog를 사용합니다. Tailwind CSS 4와 Radix 기반이며, 기존 초록색·크림색 테마와 여행 화면 배치를 유지합니다. 검색, 필터, 장소 선택, 순서 변경, 지도 조작은 공통 Button을 사용하고, 카카오 SDK가 만드는 지도 마커는 전용 DOM 요소로 유지합니다.

공통 컴포넌트는 `src/common/design-system/components/<Component>/index.tsx`, 클래스 병합 함수는 `utils/cn.ts`에 둡니다. `components.json`에 생성 위치를 지정했습니다. CLI로 컴포넌트를 추가하면 생성된 파일을 이 폴더 규칙으로 옮기고, 공통 컴포넌트와 `cn`의 import를 `@/common/design-system/...` 경로로 맞춥니다.

색상·모서리 토큰은 `shadcn.css`에서 관리합니다. `global.css`의 기본 요소 스타일은 `base`, 기존 화면 배치는 `components` 레이어에 있어 Tailwind 유틸리티로 필요한 부분을 조정할 수 있습니다. 모바일 검색 입력은 16px 글자로 표시하며, 이용 방법 안내창은 Escape로 닫고 열기 버튼으로 포커스를 돌려줍니다.

2026-09-10 적용 후 테스트 28개, TypeScript 검사와 빌드를 통과했습니다. 실제 카카오 지도에서 검색, 카페·500m 필터, 두 장소 선택, 왕복 동선 생성과 모바일 순서 변경 후 재계산을 확인했습니다. 390×844 화면에서 가로 넘침 없이 지도·일정·안내창이 표시됩니다.

## 구성

`src/pages/TripPage`는 검색·지도·일정을 배치합니다. `src/domains/trip`에는 장소와 동선 모델, 컴포넌트, 쿼리 정의, 방문 순서 계산이 있습니다. `src/common`에는 지도 SDK 로더와 공통 스타일을 둡니다. `server`는 키를 보호하면서 카카오 API 응답을 검증하고 앱의 모델로 바꿉니다.

빌드 후 `npm start`로 API와 `dist`를 함께 제공합니다. 현재 서버는 로컬 주소에만 바인딩됩니다. 외부 배포는 별도 작업이며, 이 저장소를 GitHub에 올리는 것만으로 웹사이트가 배포되지는 않습니다.
