## 문제 정의

여행 중 숙소에서 오늘 어디를 갈지 정할 때 장소 검색과 이동 경로 확인을 반복하게 된다. 사용자는 가까운 후보를 비교하고 몇 곳을 고른 뒤 하루 동선을 한 번에 보고 싶다.

neartrip은 숙소 주변의 후보를 좁히고 선택한 순서를 이동 경로로 연결한다. 날짜별 일정을 완성하거나 예약하는 일은 이번 MVP에 포함하지 않는다.

## 전체 동작 설명

### 1. 오늘 들를 곳 고르기

숙소나 출발 장소를 검색해 선택한다. 맛집·카페·가볼 만한 곳과 검색 반경을 정하면 출발점 주변의 후보가 가까운 순서로 나온다.

후보에서 이름·분류·주소·출발점과의 거리를 확인한다. 실제 장소는 카카오맵 외부 링크에서 상세 정보와 후기를 볼 수 있다. neartrip 안에 평점이나 블로그 내용을 직접 수집해 표시하지 않는다.

중간에 들를 곳은 최대 5곳이다. 방문 순서는 사용자가 정하며, 선택한 순서대로 동선을 만든다. 도착점을 따로 정하면 마지막 방문 후 도착점으로 이동하고, 생략하면 출발점으로 돌아온다.

### 2. 동선 확인하기

동선을 만들면 지도를 중심으로 이동 경로를 보여준다. 도보는 실선이고 대중교통은 점선이다. 이동 안내를 열어 구간을 고르면 해당 경로를 따라 강조 표시가 움직인다.

도보 20분과 대중교통 5정거장은 이동을 권하는 기준이다. 기준을 넘더라도 확인한 경로는 경고와 함께 보여준다. 강조 표시는 이동 미리보기이며 사용자의 현재 위치를 나타내지 않는다.

### 모바일 화면

장소 선택과 동선 보기를 두 단계로 나눈다. 첫 단계에서는 장소 목록만 스크롤한다. 두 번째 단계에서는 지도를 유지한 채 이동 안내가 아래에서 올라오고 안내 목록 안에서 스크롤한다.

## 범위

| 포함                              | 이번 MVP에 포함하지 않음                    |
| --------------------------------- | ------------------------------------------- |
| 출발점·선택 도착점과 최대 5곳     | 날짜·체류 시간·영업시간을 반영한 일정       |
| 출발점 중심의 주변 검색           | 이동 경로 주변을 따라 찾는 검색             |
| 사용자가 정한 방문 순서           | 실제 이동 시간을 기준으로 한 자동 순서 추천 |
| 구간별 실제 경로와 권장 조건 경고 | 실시간 위치 추적과 길 안내                  |
| 카카오맵 후기·상세 외부 링크      | 평점·블로그·사진의 직접 수집                |
| 예시 모드와 로컬 실행             | 로그인·여행 저장·공유·예약·서비스 배포      |

### Concept 연결

- [주변 장소 탐색](Concept-Place-Discovery.md) → [방문 계획](Concept-Trip-Plan.md): 고른 후보를 중간 방문 장소로 추가한다.
- [방문 계획](Concept-Trip-Plan.md) → [이동 안내](Concept-Route-Guidance.md): 확정한 순서의 인접 장소를 이동 구간으로 연결한다.
- [이동 안내](Concept-Route-Guidance.md) → [방문 계획](Concept-Trip-Plan.md): 이동 부담을 확인하고 장소나 순서를 다시 정한다.

## 현재 구현과 알려진 차이

정상적인 경로 응답에서 권장 조건을 넘는 경로를 유지하는 기능은 구현됐다. 다만 유효한 도보를 받은 뒤 추가 경로 조회가 일시적으로 실패하면 전체 동선이 오류로 끝나는 분기가 남아 있다. 이 차이는 [작업 현황](Implementation-Status.md)에서 미완료 티켓으로 추적한다.
